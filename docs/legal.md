## 2. MuseScore 与本项目的许可边界

- MuseScore Studio 以 **GPL-3.0** 发布。GPL 的传染性针对"衍生作品"，而通过命令行参数调用一个独立程序、只交换文件（MusicXML 进、PDF 出），通常被认为是**聚合而非衍生**。
- 因此本仓库自己的代码可以按 **MIT** 发布。**但**如果你把 MuseScore 的源码/二进制一起打包分发（例如做成绿色安装包），那部分必须遵守 GPL-3.0，并且要提供对应源码。
- 音色库（MuseSounds / MS Basic）另有许可，不能随本工具一起分发。
- **商标**：仓库名、README 里出现 "MuseScore" 属于指明兼容对象的描述性使用；不要使用 MuseScore/Muse Group 的 logo、不要暗示官方认证。若权利人提出异议，改名（例如 `dsh-sheet-music-skills`）即可消除风险。

## 3. MusicXML

MusicXML 是公开的交换格式规范（W3C Community Group Report）。生成/解析 `.musicxml` 文件本身不涉及额外授权。
MuseScore、Finale、Sibelius 等都能读写它，因此本仓库的产出**不锁定**在某个软件里。

## 4. 乐谱内容的版权（真正需要小心的地方）

识谱/扒谱的产物，在法律上通常是**复制件**或**改编作品**：

- **复制权 / 改编权**：把一段受版权保护的音乐记成谱，属于以记谱方式复制，若做了简化/移调/改配器还可能构成改编。
- **公开发布 = 分发**：把转录出的 `.mscz` / PDF / 音频上传到 GitHub、网盘、视频平台，属于向公众提供复制件，需要许可。**这是最常见的侵权场景**，不是"我自己弹弹"。
- **"个人学习使用"范围很窄**：中国《著作权法》第 24 条的合理使用限于"为个人学习、研究或者欣赏，使用他人已经发表的作品"，且不得影响作品正常使用、不得不合理损害权利人利益；美国 fair use 是四要素平衡测试。两者都**不覆盖公开分发**，也不覆盖商业使用。
- **版本也有版权**：巴赫的作品本身是公有领域，但现代校订版（Urtext）、排版、译配歌词可能另有版权；别把"作曲家去世 70 年以上"直接等同于"这份 PDF 可以随便用"。
- **站点条款**：从 musescore.com 等平台下载的内容受其服务条款约束，付费/订阅内容不能因为"技术上能拿到"就二次分发。

对本仓库的使用建议：

1. 处理自己的作品、公有领域作品、或你有明确授权的谱；
2. 生成的产物放本地，不要因为"顺手"就提交到公开仓库；
3. 开源项目里需要示例时，用程序生成的乐谱（如 `assets/example_score.json`）或公有领域旋律。

## 5. 识谱（OMR）工具本身的定位

- 工具具有**实质性非侵权用途**（整理自己的手稿、重排公有领域乐谱、无障碍转换等），这与 Audiveris、PhotoScore、SmartScore 等商业/开源 OMR 软件是同一类。
- 但工具的中立性**不延伸到**：帮助绕过技术保护措施（破解加密 PDF、绕过 DRM）、批量抓取受条款限制的站点内容。本项目不实现这些能力，也不应被改造用于这些用途。
- 如果用于教学/出版流程，建议保留"来源与授权"记录（原谱出处、许可方式），这在被质疑时是最有用的证据。
